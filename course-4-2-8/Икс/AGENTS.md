# Икс — локальные правила предмета

Этот файл дополняет корневой `AGENTS.md` университетского архива и действует
для всех работ в `course-4-2-8/Икс`. Явные указания пользователя и требования
методических указаний определяют содержание конкретной работы.

- Группа — ИТз-221
- Номер варианта для предмета «Икс» — **9**, пока пользователь явно не сообщит

## Источники и оформление

- `docs/` — источник заданий, исходных данных варианта, методики выполнения
  и требований преподавателя
- `reference/` — только примеры оформления отдельных заданий: как представить
  расчёт, расположить пояснения, таблицы, команды и иллюстрации внутри задания
- Не заимствовать из `reference/` оформление документа в целом: шапку, поля,
  шрифты, интервалы и общую структуру отчёта. Не переносить чужие решения,
  результаты, скриншоты и данные студента
- Примеры оформления заданий не заменяют требования методички и не являются
  основанием менять методику решения
- Параметры существующего пользовательского отчёта сохранять. Для нового
  отчёта основу оформления согласовывать отдельно

## Отчёты по сетевым лабораторным работам

- Общие правила краткого студенческого изложения, оформления команд,
  иллюстраций и контрольных ответов хранить в навыке Study Report; правила
  этого предмета дополняют их, а не задают стиль отчётов по другим дисциплинам
- Цель, формулировки пунктов задания и контрольных вопросов брать из
  методички. Исходные данные приводить только для варианта 9, без повторных
  оговорок о варианте в тексте
- Расчёты подсетей и сведения об узлах и интерфейсах оформлять в таблицах
  по методичке, сохраняя требуемые столбцы. Проверять согласованность IP,
  масок, границ подсетей, broadcast, шлюзов, интерфейсов и известных MAC
- Настройку внутренней сети VirtualBox показывать на примере одного
  адаптера; остальные описывать кратко, сохраняя соответствие адаптеров,
  сетей и адресов в таблице. Не описывать включённый по умолчанию
  виртуальный кабель как отдельный этап
- Аналогичные действия на Linux-клиентах описывать совместно, если
  пользователь подтвердил одинаковый функциональный результат. Снимок
  одного клиента может иллюстрировать общее описание, но его измерения
  нельзя приписывать второму клиенту или переименовывать машину на снимке
- Проверки связи описывать по фактически использованным IP-адресам и
  доменам. Не добавлять служебные замечания о согласованной замене домена;
  оригинальную формулировку задания при этом сохранять. Несогласованные
  существенные расхождения с заданием выносить на обсуждение
- В проверках ping фиксировать доступность и существенные потери пакетов,
  а не перечислять задержки каждого запуска, если их анализ не требуется.
  Не переносить численные результаты между клиентами
- Различать маршруты, добавленные командами в текущем сеансе, и настройки,
  сохранённые в конфигурации. Не утверждать сохранение после перезагрузки
  без подтверждения
- Подтверждённую настройку брандмауэра Windows описывать кратко, например:
  добавил правило для входящих ICMP-запросов из лабораторной сети.
  Не приводить длинную команду,
  если её текст не требуется заданием. Не включать в отчёт подробности
  включения или отключения VPN при устранении неполадок

## Согласование каждого задания

Перед внесением каждого задания или согласованного связанного блока в отчёт:

1. Изучить соответствующее задание методички, данные варианта и уже
   выполненную часть работы
2. Представить пользователю предлагаемое решение: расчёты либо порядок
   настройки, команды, ожидаемый результат и способ проверки
3. Показать будущее оформление задания: последовательность текста, расчётов,
   таблиц, изображений и подписей; указать необходимые фактические данные
   и скриншоты
4. Дождаться явного согласования решения и оформления, затем внести только
   согласованный объём

- Согласование одного задания не распространяется автоматически на следующие
- Существенные изменения согласованного решения обсуждать повторно
- Ожидаемые результаты не выдавать за полученные; отсутствующие результаты
  обозначать явными подписанными плейсхолдерами
- Ошибки и неоднозначности методички выносить на обсуждение, не исправляя
  учебные требования самостоятельно
