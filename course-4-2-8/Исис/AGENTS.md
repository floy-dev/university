# Исис — локальные правила предмета

Этот файл дополняет корневой `AGENTS.md` архива. Он действует для всех работ
предмета «Исис» в `course-4-2-8/Исис`. Методические указания в `docs/` и
явные указания пользователя имеют приоритет при конфликте.

## Параметры студента и проекта

- Базовое пространство имён: `ru.bstu.itz221.dmitriev`.
- Пакет каждой лабораторной: `ru.bstu.itz221.dmitriev.labN`, где `N` — номер
  лабораторной работы.
- Номер варианта — **9**. Использовать вариант 9 во всех таблицах вариантов,
  если в методичке не установлено другое правило.
- Базовая версия языка и среды — JDK 26. Не использовать возможности,
  отсутствующие в выбранной версии JDK.

## Единый проект и защита

Все пять лабораторных готовятся к одной защите как практическое задание по
пятой лабораторной работе.

- Итоговая система представляет собой один основной Java-проект с пакетами
  `lab1`, `lab2`, `lab3`, `lab4` и `lab5`; дополнительные пакеты допустимы для
  запуска, моделей, обработчиков и вспомогательного кода.
- Лабораторные запускаются из отдельного пакета-диспетчера либо из кода уровнем
  выше пакетов `labN`. Пользователь выбирает работу из меню, после выполнения
  возвращается в меню, а приложение не перезапускается.
- Не использовать `while (true)` и циклы с неизменяемой логической переменной.
  У цикла должно быть явное изменяемое условие завершения.
- Не переносить и не реорганизовывать уже созданные лабораторные автоматически.
  Объединение текущих проектов в единый проект выполнять только по явному
  заданию пользователя.

## Ввод, вывод и обработка данных

- Реализация заданий находится в отдельных классах и вызывается из точки
  входа `main` через осмысленные методы.
- Для ЛР3 и последующих работ предусмотреть ввод параметров как из консоли,
  так и из файла. Это правило сохраняется для всего итогового приложения.
- Реализовать интерфейс для ввода и вывода данных, который позволяет выбрать
  консольный или файловый режим без дублирования алгоритмов лабораторных.
- Парсинг пользовательского ввода должен быть понятным и устойчивым:
  полностью нечисловой ввод (например, `ыва`) запрашивается повторно; строка,
  содержащая число и посторонние символы в начале или конце (например,
  `1авы`, `2ыва4`), преобразуется к числу 1 или 2 с уведомлением пользователя
  об исправлении. Применять такую обработку и к `double`, когда тип требуется
  вариантом.
- Уведомлять пользователя о выполненных автоматических исправлениях и важных
  действиях программы.
- Сохранять учебный уровень кода и ориентироваться на уже выполненные задания
  этой лабораторной. Не строить сложную архитектуру и не добавлять классы,
  модели, абстракции или универсальные механизмы без необходимости задания.
- Использовать простые массивы и стандартные коллекции только там, где они
  непосредственно упрощают решение. Классы-обёртки и `enum` применять только
  при реальной необходимости.

## XML и база данных для ЛР5

- Реализовать единый интерфейс доступа к данным для XML- и DB-обработчиков.
  Он должен включать операции создания, удаления, обновления, преобразования,
  чтения всех записей, чтения по идентификатору и чтения по фильтрам.
- Реализации XML и БД взаимозаменяемы через ссылку на этот интерфейс; выбор
  режима XML/БД не должен требовать изменения прикладной логики.
- Для XML использовать SAX для чтения и DOM для записи. Реализовать CRUD в
  обоих форматах, конвертацию XML ↔ БД и поиск по одному или нескольким
  параметрам; для числовых параметров поддержать поиск минимального и
  максимального значения.
- Поддерживать не менее 10 записей в XML или БД. В `.properties` хранить
  настройки подключения к БД, рабочий каталог, ограничения варианта и тексты
  информационных сообщений и ошибок.

## Требования методических указаний

- Исходный путь повторяет пакетную иерархию. В каждом файле Java допускается
  один `public` класс или интерфейс, имя файла совпадает с его именем.
- Исполняемый класс содержит `public static void main(String[] args)`.
- Для каждого задания создаётся отдельный метод с осмысленным названием.
- Javadoc и комментарии к классам и методам не добавлять, если пользователь не
  запросил их отдельно.
- ЛР2 приводит ЛР1 к конвенции Java и добавляет Log4j-логирование основных
  действий в консоль и файлы с уровнями INFO, DEBUG, WARNING, ERROR и FATAL.
- ЛР3 требует иерархию классов; ЛР4 — решение варианта с регулярными
  выражениями.
- Для сдачи каждой лабораторной подготовить отчёт, исходный код, результаты
  запуска и скомпилированные `.class`-файлы или `.jar`, а также скрипты запуска
  для Windows (BAT) и Linux (Shell). Отчёт включает тему и цель, данные
  студента, задание, теорию, описание алгоритмов и решений, результаты,
  исходный код и выводы.
